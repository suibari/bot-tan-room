# プレゼントの審査

新規プレゼントは `src/lib/giftModeration.ts` の基準で審査する。
政治・宗教、暴力・差別・性的表現などの既存の拒否対象に加え、排泄物・体液そのものやそれらを含む物、嫌がらせ・侮辱を目的とする贈り物を拒否する。
衛生用品などは関連語だけで拒否せず、贈り物の意味で判断する。

審査ルールはシステム指示に置き、入力はJSONデータとして渡す。
構造化出力を要求し、サーバーでもJSON全体の形式と真偽値の型を検証する。

- `{"isAcceptable":true}`：保存、行動生成用イベント記録、親密度加算、お礼生成へ進む。
- `{"isAcceptable":false}`：HTTP 400と日英の定型メッセージで拒否する。
- 空応答、不正JSON、判定欠落、型違い、余分なフィールド、API障害：HTTP 503と再試行案内を返す。

拒否・審査失敗では保存せず、1日1回の枠も消費しない。既に保存されたプレゼントの再審査や削除は行わない。

## 自動テスト

```bash
node --test tests/*.test.cjs
npx tsc --noEmit --incremental false
npm run lint
```

APIとDBをモックし、受理条件と、拒否・審査失敗時に副作用が発生しないことを確認する。
これだけでは実モデルが各入力を正しく分類できることは確認できない。

## 実モデルの検証

`GEMINI_API_KEY` を環境変数に設定した環境で実行する。キーをコマンドや検証結果に直接記載しない。

```bash
node scripts/check-gift-moderation.cjs
```

本番APIと同じ審査リクエストと判定処理で、14例を各3回、計42回評価する（再試行時は追加のAPI呼び出しが発生する）。
本番DBへの保存やお礼生成は行わない。モデル呼び出しにはAPI利用料金がかかる。
排泄物、表記揺れ、英語、嫌がらせ、審査への干渉を拒否する一方、花束と衛生用品を許可することを確認する。
不一致または審査失敗が1回でもあれば終了コード1になる。

本番反映前にはこの検証を実行し、結果を確認する。有限の例での成功はすべての入力に対する拒否を保証するものではないため、モデルや基準を変更した場合も再実行する。
